EVIA Paradigma. ուղեցույց

EVIA Paradigma-ն տեսողական ծրագրավորում է. բլոկները գունապնակից քաշեք կտավի վրա, միացրեք դրանք կապերով և սեղմեք Run։ Նույն ծրագիրը կարելի է վերածել C (C99, C11, C17) կամ C++ (C++98-ից մինչև C++20) կոդի և կառուցել Clang-ով կամ GCC-ով, ինչպես նաև Arduino և ESP32 տախտակների կոդի։ Ծրագրի ինտերֆեյսն անգլերեն է, ուստի ընտրացանկերի և կոճակների անունները բերված են այնպես, ինչպես երևում են էկրանին։

Միջերեսն ինքը նույնպես կարող է լինել անգլերեն, ռուսերեն կամ հայերեն՝ Կարգավորումներ > Միջերեսի լեզուն։ Ընտրացանկերը, կոճակները, ներկապնակը և բլոկների անունները փոխվում են դրա հետ. ստեղծված կոդը և կոմպիլյատորների հաղորդագրությունները մնում են անգլերեն։ Փոփոխությունը ուժի մեջ է մտնում EVIA Paradigma-ի հաջորդ գործարկման ժամանակ։

  1. Կտավի վրա քաշեք Start-ը, մի քանի բլոկ և End-ը։
  2. Բլոկի ներքևի փոքր շրջանից (նրա ելքի պորտից) քաշեք դեպի մեկ այլ բլոկ՝ դրանք միացնելու համար։
  3. Բլոկի վրա կրկնակի սեղմումը բացում է նրա կոդը խմբագրելու համար։
  4. Մկնիկի անիվը սխեմայի վրա մոտեցնում և հեռացնում է այն ցուցիչի ուղղությամբ։
  5. Սեղմեք Run (F5)։ Ելքը երևում է ներքևի վահանակում. կատարվող բլոկը լուսավորվում է։
  6. Գործիքագոտում ընտրեք Language և սեղմեք Generate code (F7)՝ ծրագիրը տեսնելու, պահելու, կառուցելու և գործարկելու համար։

Տեսք և լեզու։ View > Theme-ը ընտրում է IntelliJ-ի բաց թեման, Darcula մուգ թեման կամ ձեր համակարգի կարգավորումը. թեման փոխվում է անմիջապես և հիշվում է։ Բաժինների ցանկի վերևում կարելի է ընտրել այս ուղեցույցի լեզուն՝ անգլերեն, ռուսերեն կամ հայերեն։

Արտահայտություններ

Արժեքները թվեր են կամ տեքստ։ Օպերատորները՝ ցածրագույն առաջնահերթությունից դեպի բարձրագույն.

  • ||   &&
  • == != < <= > >= (տեքստերը համեմատվում են այբբենական կարգով)
  • + - (+-ը միացնում է տեքստը, եթե որևէ կողմը տեքստ է)
  • * / %
  • ունար - և !, փակագծեր

Տեքստը գրվում է կրկնակի չակերտներով. թույլատրվում են \", \\, \n escape-հաջորդականությունները։ Պայմանը ճշմարիտ է, եթե դա ոչ զրոյական թիվ է կամ ոչ դատարկ տեքստ։

Դասեր և օբյեկտներ

Դասը միավորում է դաշտերը (տվյալներ, որոնք պահում է յուրաքանչյուր օբյեկտ) և մեթոդները (բլոկային ծրագրեր, որոնք աշխատում են այդ տվյալների հետ)։ Ստեղծեք այն Edit > New Class-ով, գունապնակի + New class-ով կամ նշեք բլոկները և սեղմեք Ctrl+G՝ դրանք դաս դարձնելու համար։

  • Fields ներդիրը. յուրաքանչյուր դաշտի անունը և սկզբնական արժեքը։ Սկզբնական արժեքները արտահայտություններ են և կարող են օգտագործել ծրագրի փոփոխականները և նախորդ դաշտերը։ Մեթոդների ներսում դաշտը գրվում է this.անուն։
  • Մեկ ներդիր յուրաքանչյուր մեթոդի համար. նրա անունը, պարամետրերը և մարմինը։ Մարմինը սկսվում է Enter-ով և ավարտվում Exit-ով։ Յուրաքանչյուր առանձին Exit անուն դառնում է կանչող բլոկի ելքային պորտ, օրինակ՝ yes / no։ Պարամետրերը գալիս են որպես դաշտեր. n պարամետրը կարդացվում է որպես this.n։
  • Կոնստրուկտոր. init անունով մեթոդ (կոճակ՝ + Constructor)։ Օբյեկտ ստեղծելիս նրա դաշտերը նախ ստանում են սկզբնական արժեքները, ապա մեկ անգամ կատարվում է init-ը։

Մեթոդը կանչելու համար այն գունապնակի Classes բաժնից քաշեք կտավի վրա։ Բլոկի վրա աջ կամ կրկնակի սեղմումով ընտրվում են մեթոդը, օբյեկտը և արգումենտները։ Նույն օբյեկտի անունով բլոկները աշխատում են մեկ օբյեկտի հետ (և նրա դաշտերի). առանց օբյեկտի անվան բլոկն ունի իր սեփական օբյեկտը։ Օբյեկտները ստեղծվում են առաջին օգտագործման ժամանակ։

Մոդուլներ

Մոդուլը (*.eviam) դասերի ֆայլ է, որը կարող են օգտագործել մի քանի ծրագրեր։

  • File > Export Classes as Module-ը դասերը տեղափոխում է մոդուլի ֆայլ։ Ծրագիրն այնուհետև հղվում է մոդուլին, և ծրագիրը պահելիս պահվում է նաև մոդուլը։
  • File > Import Module-ը մոդուլի դասերը ավելացնում է բաց ծրագրին։
  • Դասի պատուհանը ցույց է տալիս, թե որտեղ է պահվում դասը։

Նախագծեր

File > New Project-ը ստեղծում է թղթապանակ՝ ծրագրին անհրաժեշտ ամեն ինչով.

MyProject/
  MyProject.eviaproj   նախագծի կարգավորումներ
  main.evia            գլխավոր ծրագիրը
  modules/             դասերի մոդուլներ
  build/               գեներացված կոդ (չի մտնում commit-ների մեջ)
  README.md
  .gitignore

Նախագիծը նորից բացեք File > Open Project-ով (ընտրեք թղթապանակը կամ .eviaproj ֆայլը)։ Նախագծում մոդուլները ներմուծվում են modules/-ից և արտահանվում են այնտեղ, իսկ Generate code-ը լրացուցիչ գրում է build/<անուն>.c կամ .cpp։ Նախագիծը հիշում է իր լեզուն։

Git և GitHub

Git ընտրացանկը գործարկում է ձեր համակարգչում տեղադրված git-ը և օգտագործում է արդեն կարգավորված մուտքը (Git Credential Manager, SSH բանալի կամ gh auth login)։ EVIA Paradigma-ն երբեք չի խնդրում և չի պահում գաղտնաբառեր կամ թոքեններ։

  • Initialize Repository. git init main ճյուղում (նոր նախագծերը դա անում են ինքնուրույն, եթե git-ը տեղադրված է)։
  • Commit (Ctrl+K). պահում է ծրագիրը և commit է անում բոլոր փոփոխությունները. հաղորդագրության խմբագրիչում աշխատում են Vim ստեղները։
  • Connect to GitHub. մուտքագրեք սեփականատեր/պահոց կամ կլոնավորման URL։ Create repository on GitHub-ը բացում է github.com-ը զննարկչում՝ անունն արդեն լրացված. ստեղծեք դատարկ պահոց և սեղմեք OK։
  • Push / Pull. commit-ները ուղարկել GitHub / ստանալ նորերը (միայն fast-forward, այնպես որ ոչինչ չի միաձուլվում ձեր գիտությունից թաքուն)։
  • History-ն ցույց է տալիս վերջին commit-ները. Open on GitHub-ը բացում է պահոցի էջը։

Տեղադրեք git-ը git-scm.com-ից, եթե ընտրացանկը ասում է, որ այն բացակայում է։

Գեներացված կոդ. C և C++

Generate code (F7)-ը ամբողջ ծրագիրը վերածում է մեկ սկզբնական ֆայլի։ Գործիքագոտու երեք բացվող ցանկերը (և կոդի պատուհանում) որոշում են արդյունքը. նույն ընտրությունները կան Run > Code Language and Mode-ում։ Կոդի պատուհանում դրանք փոխելիս կոդը նորից է գեներացվում։

ՑանկՏարբերակներԻնչն է փոխվում
LanguageC99, C11, C17
C++98, C++11, C++14, C++17, C++20		 C. յուրաքանչյուր դասի համար struct և Class_m_method(self, ...) ֆունկցիաներ, փոքր runtime՝ միայն այն օգնականներով, որոնք օգտագործում է ծրագիրը։ C++. յուրաքանչյուր դասի համար անդամ-ֆունկցիաներով struct. C++98-ը օգտագործում է սովորական ցուցիչներ, C++11/14-ը՝ std::unique_ptr, C++17/20-ը՝ std::variant և std::to_chars։
FlowStructured
Goto		 Structured. if/else, for, while, do/while և switch (պիտակներ՝ միայն այնտեղ, որտեղ կապերը չեն տեղավորվում բլոկային կառուցվածքի մեջ)։ Goto. յուրաքանչյուր բլոկ պիտակ է, իսկ յուրաքանչյուր կապ՝ անցում, ամենամոտը սխեմային։

Fast		 Safe. թվեր և տեքստ՝ ինտերպրետատորի բոլոր ստուգումներով (չսահմանված փոփոխականներ, բաժանում զրոյի, թիվ չհանդիսացող տեքստ, անվերջ ռեկուրսիա)։ Fast. պարզ double փոփոխականներ և դաշտեր, տեքստ՝ միայն Print-ում, առանց կատարման ժամանակի ստուգումների։ Այն ծրագիրը, որը տեքստ է պահում փոփոխականում, չի կարող օգտագործել Fast արժեքներ. MQTT։ Ցանցի անունը, գաղտնաբառը, բրոքերը և թեմաները ֆիքսված տեքստեր են, քանի որ դրանք գրվում են ծրագրի մեջ կառուցելիս։ PIC32 C-ն AT որոնվածքով ESP8266 կամ ESP32 մոդուլ է վարում UART2-ով (RB5/RB1՝ 28-կոնտակտանի չիպերում, RF4/RF5՝ մյուսներում), այնպես որ Print-ը մնում է UART1-ին։ Arduino-ն ESP32 տախտակի վրա օգտագործում է տախտակի սեփական WiFi-ը։ Run-ը պատասխանում է ձեր համակարգչի բրոքերից՝ բաժանորդագրված թեմայում հրապարակելը վերադարձնում է հաղորդագրությունը։ AVR տախտակը մերժում է MQTT բլոկները (մեկ սերիական պորտ, որը զբաղեցնում է Print-ը), FPGA-ն նույնպես։ Հաղորդագրությունը թիվ է՝ գրված այնպես, ինչպես Print-ն է գրում. քանի որ -1-ը նաև նշանակում է «ոչինչ չի եկել», MQTT Has Message-ը տարբերում է իրական -1-ը։ MQTT-ն կարող է անցնել նաև MX695F512L, MX795F512L չիպերի և Ethernet Starter Kit II-ի սեփական Ethernet պորտով. կարգավորումներում ընտրեք PIC32-ի MQTT-ն՝ → Ethernet, և գեներացված ֆայլը դառնում է MPLAB X Harmony ծրագրի հավելված, որը բերում է TCP/IP փաթեթը։ Այս ուղին փորձարարական է. այն այստեղ կոմպիլացվում է վերնագրերի կաղապարներով, բայց երբևէ չի կառուցվել իրական Harmony-ով և չի աշխատեցվել տախտակի վրա, այդ պատճառով ստուգվածը մնում է WiFi մոդուլը։

MQTT Ethernet-ով (փորձարարական)։ MX695F512L-ի, MX795F512L-ի և PIC32 Ethernet Starter Kit II-ի համար Settings > PIC32 > PIC32 MQTT over > Ethernet-ը ստացվող ֆայլը դարձնում է MPLAB X Harmony նախագծի հավելված՝ TCP/IP փաթեթը տալիս է Harmony-ն, կազմաձևումը, տակտը և main()-ը մնում են նախագծին, իսկ դուք այնտեղից կանչում եք app_run()։ Միացրեք TCP-ն, DHCP և DNS հաճախորդները, Ethernet MAC վարորդը և տախտակի PHY-ը (LAN8740 այս հավաքածուում)։ Հասցեն տալիս է DHCP-ն, ուստի ցանցի անունը և գաղտնաբառը չեն օգտագործվում։ Այս ուղին ստուգումներում կոմպիլացվում է վերնագրերի կրկնօրինակներով, բայց չի կառուցվել իրական Harmony-ով և չի գործարկվել տախտակի վրա. ստուգվածը WiFi մոդուլն է։

Պինները կարող են լինել թվեր, արտահայտություններ կամ տախտակի LED_BUILTIN, A0 ... A15 անունները. HIGH և LOW աշխատում են ցանկացած արտահայտության մեջ։ Այս անունները չի կարելի օգտագործել որպես փոփոխականներ։

Գծերի (bus) բլոկները աշխատում են Run-ում և տախտակների բոլոր երեք լեզուներում։ Օգտագործելուց առաջ գիծը պետք է բացել. հասցեները 7-բիթանոց են, թվերը՝ տասնորդական (80-ը 0x50-ն է)։ PIC32-ում պինները ֆիքսված են չիպի ընտանիքի համար և նշված են ստեղծված կոդի սկզբում (չիպի UART1, SPI և I2C1)։ Run-ը նմանակում է գծերը. UART-ի հաղորդիչը միացված է նրա ընդունիչին, ուստի UART Write-ի բայթերը վերադառնում են UART Read-ով (և երևում են նաև ելքում որպես տեքստ), SPI-ի մուտքը միացված է նրա ելքին, իսկ 80 հասցեով պատասխանում է 256 ռեգիստրով մեկ I2C սարք։

Run-ը նմանակում է Arduino Uno. պինների փոփոխությունները ելքում երևում են board [500 ms] pin 13 HIGH տեսքով, ժամանակը առաջ է գնում միայն Delay-ում (գլխավոր պատուհանը նաև իրականում սպասում է, եթե արագության սահողը լրիվ արագության վրա չէ), յուրաքանչյուր մուտքային պինի կոճակը սեղմվում է ամեն 2 վայրկյանի երկրորդ կեսին, իսկ անալոգային պինները կարդում են դանդաղ 0..1023..0 ալիք։ Ծրագիրը կատարվում է մեկ անգամ, կարծես setup()-ից. դրանից հետո պինները պահում են իրենց վիճակը։ File > Open Example > Arduino Boards, ESP32 Boards, PIC32 Boards և STM32 Boards-ում կան օրինակներ՝ blink, button, fade, analog meter, Led դաս և UART, SPI ու I2C օրինակներ։

Համակարգչի լեզուները (C, C++) չեն կարող օգտագործել Board բլոկները. Generate code-ը կասի, թե որ բլոկը փոխել։

Փաթեթներ և թարմացումներ

Գործիքակազմերը EVIA սերվերի (evia.am) փաթեթներն են՝ arduino-cli, avr-gcc avrdude-ով, Arm GNU Toolchain, OpenOCD և OSS CAD Suite։ Տեղադրված պատճենի առաջին մեկնարկին ծրագիրը հարցնում է, թե որոնք ներբեռնել. Settings > Packages and Updates-ը (կամ Help > Check for Updates-ը) ցույց է տալիս, թե ինչ է տեղադրված և ինչ կա, և տեղադրում, թարմացնում կամ հեռացնում է դրանք։ Settings-ի Get կոճակները նույն կերպ են ներբեռնում մեկ գործիք։ Յուրաքանչյուր ներբեռնում ստուգվում է օգտագործելուց առաջ, և ադմինիստրատորի իրավունքներ պետք չեն. փաթեթները ձեր սեփական տվյալների թղթապանակում են։

EVIA Paradigma-ի նոր տարբերակը նույնպես փաթեթ է. այն տեղադրվում է ձերի կողքին և մեկնարկում հաջորդ անգամ (կամ անմիջապես Restart Now-ով)։ Ոչինչ չի հեռացվում։ Հրամանի տողում՝ --packages, --install ID (կամ --install updates) և --remove ID։

Terminal-ը (գործիքագոտի կամ Help > Terminal) բացում է իրական տերմինալ սալիկի հաջորդական պորտում (UART՝ պորտ, արագություն, ինչ է ուղարկում Enter-ը, տեղական արձագանք) կամ մեկ այլ համակարգչում SSH-ով (գաղտնաբառ կամ բանալի)։ Յուրաքանչյուր նիստ ունի իր ներդիրը. Upload-ից առաջ փակեք ներդիրը, քանի որ նրան պետք է պորտը։

FPGA՝ Artix-7 և GateMate

Եվս երեք լեզու՝ SystemVerilog, Verilog-2001 և VHDL (VHDL-2008), նույն սխեման դարձնում են սարքակազմ։ Յուրաքանչյուր բլոկ վերջավոր ավտոմատի մեկ վիճակ է և տևում է մեկ տակտ։ Փոփոխականները նշանով 32-բիթանոց ռեգիստրներ են։

Կոնտակտները ֆիքսվում են կառուցելիս, ուստի կոնտակտը պետք է լինի թիվ կամ անուն՝ LED0, SW3, BTNC, BTN0, JA1։ Եթե տախտակը այդպիսի կոնտակտ չունի, սխալը ցույց է տալիս առկաների ցանկը։ Կոնտակտը չի կարելի միաժամանակ կարդալ և գրել։

Ամբողջ թվեր։ Թվաբանությունը 32 բիթով շրջվում է; / և % կլորացնում են դեպի զրո, 0-ի բաժանումը տալիս է 0։ Գործարկումը օգտագործում է double թվեր, ուստի 5 / 2-ը Գործարկման մեջ 2.5 է, իսկ FPGA-ում՝ 2։ Դեռ չեն աջակցվում՝ դասերը, Input, Analog Read, SPI, I2C և տեքստը փոփոխականներում (Print-ում տեքստը աշխատում է)։

Կառուցում և բեռնում։ Artix-7՝ Vivado խմբաքանակային ռեժիմով կամ բաց շղթա (yosys, nextpnr-xilinx, Project X-Ray), ընտրվում է Կարգավորումներում։ GateMate՝ yosys, nextpnr-himbaechel, gmpack։ Բեռնումը՝ Vivado կամ openFPGALoader։ Կոնտակտների սահմանափակումները ֆայլի առաջին մեկնաբանության մեջ են, իսկ հրամանի տողում -o-ն գրում է նաև .xdc կամ .ccf ֆայլ։

Ստուգված է՝ սիմուլյացիա՝ Գործարկման հետ համեմատած, և սինթեզ բաց գործիքներով։ Ստուգված չէ՝ Vivado, openXC7 և իրական տախտակներ։

Օրինակներ՝ File > Open Example > FPGA Boards։

Linux պատկերներ

Linux > Նոր Linux պատկեր-ը բացում է պատուհանը՝ տախտակ, թղթապանակ (առանց բացատների ճանապարհում), հոսթի անուն, root գաղտնաբառ, SSH սերվեր, Python 3, լրացուցիչ փաթեթներ (հավաքման համակարգի անուններով)։ Հավաքել պատկերը-ն առաջին անգամ ներբեռնում է աղբյուրները, կիրառում ընտրությունները և հավաքում․ արդյունքը երևում է պատուհանում։ Menuconfig-ը տերմինալում բացում է հավաքման համակարգի սեփական ընտրացանկը։ Գրել SD քարտի վրա-ն ցույց է տալիս միայն SD քարտերը և USB կրիչները, հարցնում է երկու անգամ և գրելու համար խնդրում ձեր գաղտնաբառը։

Ամեն ինչ թղթապանակում է՝ evia-linux.json (ընտրությունները) և build.sh, որը կարելի է գործարկել նաև ինքնուրույն՝ ./build.sh all։ Root գաղտնաբառը պահվում է secrets/-ում և հասանելի է միայն ձեզ․ պատկերը ստանում է միայն դրա հեշը։

Հավաքումն աշխատում է Linux-ում (Windows-ում՝ WSL 2, Mac-ում՝ Linux վիրտուալ մեքենա)։ Ստուգել համակարգիչը-ն ցույց է տալիս, թե ինչ է պակասում, և տեղադրման հրամանը։ BeagleBone Black-ը քարտից բեռնվում է, եթե միացնելիս սեղմած պահեք S2 կոճակը․ Raspberry Pi 5-ը բեռնվում է ինքնուրույն։ Հետո Տերմինալ-ը միանում է UART-ով (115200) կամ SSH-ով։ Հրամանի տողում՝ --linux DIR --system yocto --board bbb։

Աղբյուրները որպես փաթեթներ։ Buildroot-ը, Yocto-ն (Poky և meta-raspberrypi) և OpenWrt-ը (երկու տախտակների Image Builder-ներով) EVIA սերվերի փաթեթներ են՝ պատուհանի Ստանալ աղբյուրները կոճակը կամ Կարգավորումներ > Փաթեթներ և թարմացումներ, «Linux images» խումբ։ build.sh-ը աղբյուրները վերցնում է տեղադրված փաթեթից, իսկ առանց դրա ներբեռնում է նույն ամրագրված ֆայլերը և ստուգում դրանց SHA-256-ը։ Հավաքումն ինքը դեռ ներբեռնում է իրեն անհրաժեշտ կոմպիլյատորներն ու փաթեթները։
