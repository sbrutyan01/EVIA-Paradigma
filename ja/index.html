プログラムを描き、
言語を選ぶ。

EVIA Paradigmaは、コンピューターが受け取る内容を見たい人のためのビジュアルプログラミング環境です。図がプログラムそのもので、言語は設定にすぎません。キャンバス上でブロックをつないで実行し、C99からC++20（ClangまたはGCC）、Python 3・Java・Kotlinのプログラム、Androidアプリ、Arduinoスケッチ、AVR・PIC32・STM32チップ向けのベアメタルC、FPGA向けのSystemVerilog、Verilog、VHDLから出力先を選べます。

EVIA 0.12.1 をダウンロード GitHubでソースを見る

Windows、macOS、Linuxに対応。無料のオープンソース、MITライセンス。

できること

プログラムはブロックと接続線で構成

Start、Set、Input、Print、If/Else、For、While、Do-Whileはブロックです。ブロック間の接続線が制御フローを表します。Runを押すと、実行中のブロックが強調表示されます。数値やテキストを使った式に対応し、&& || !、比較演算、一般的な算術演算も利用できます。

クラス、オブジェクト、モジュール

クラスには初期値を持つフィールド、コンストラクター、メソッドがあります。各メソッドはEnterからExitまでの独立したブロック図です。各Exitは呼び出し側ブロックの出力になります。同じオブジェクト名を使うブロックは、同じオブジェクトを共有します。クラスをモジュール（.eviam）として保存し、ほかのプログラムにインポートできます。

1つの図から19種類の言語へ

図が表すのはプログラムの動作であり、記述言語ではありません。同じキャンバスから8種類のC/C++標準、Python 3、Java、Kotlin、Androidアプリ、Arduinoスケッチ、ベアメタルAVR・PIC32・STM32 C、FPGA向けのSystemVerilog、Verilog-2001、VHDLを生成できます。Runは図そのものを実行するため、出力を各生成版と比較できます。出力先が対応できないブロックがある場合、意味を黙って変えるのではなく、そのブロックをエラーで示します。

8種類のC/C++標準と2種類の記述方法

ツールバーからC99、C11、C17、C++98、C++11、C++14、C++17、C++20を選択できます。Structuredはif/else、ループ、switchを生成し、Gotoは各ブロックをラベル、各接続線をジャンプに変換します。Safe値はテキストとインタープリターのすべてのチェックを維持し、Fast値は実行時チェックのない単純なdoubleです。Cランタイムにはプログラムが使う機能だけが含まれるため、-Wall -Wextra -Wpedantic -Werrorで警告なくコンパイルできます。

Python 3、コンパイル不要

Python 3を選ぶと、同じ図からPython 3.8以降で動く .py ファイルが1つ生成されます。パッケージもコンパイラーも不要です。クラスはPythonのクラスに、プログラム変数はモジュールのグローバル変数になります。コードウィンドウのRunでプログラムを実行でき、Inputに入力したテキストはプログラムに渡されます。Pythonにはgotoがないため、Structuredはif/elseとwhileループを書き、Gotoはブロックごとに1つの分岐を持つ小さな状態機械になります。Print、Input、数値の表記、すべてのエラーメッセージはインタープリターと同じです。

ブロックのコードを確認

ブロックを右クリックしてView source codeを選ぶと、生成ファイルが開き、そのブロックに対応する行が正確に強調表示されます。選択した言語でメソッド全体やクラス全体を確認することもできます。Compile & RunはClangまたはGCCでその場でビルドします。Windowsではアプリがllvm-mingwまたはWinLibs GCCをインストールするため、Visual Studioは不要です。

ArduinoとESP32ボード

Pin Mode、Digital Write and Read、Analog Read and Write、Delay、Millisもブロックとして使えます。ArduinoスケッチはUno、Nano、Mega 2560、Leonardo、Micro、Pro Miniのほか、ESP32、ESP32-S2、-S3、-C3、-C6、-H2向けにビルドできます。Runはコンピューター上でUnoをシミュレートし、ピンの変化をすべて出力するので、実機がなくてもプログラムを試せます。 UART、SPI、I2C、MQTT もブロックです。

レジスターまで扱うベアメタル

AVR CではArduinoコアを使わず、ATmega328P、ATmega2560、ATmega32U4向けのプログラムを作成できます。ポート、タイマー、PWM、ADC、UARTを読みやすいCで設定します。avr-gccで約4 KBにビルドでき、Uploadからavrdudeでボードに書き込めます。各例はsimavrで実行し、インタープリターと照合されます。

0.5の新機能：PIC32 CはMicrochip XC32を使い、9種類のPIC32MXチップにも対応しました。UART、SPI、I2CはRunと3種類すべてのボード言語でブロックとして利用できます。PIC32コードはMicrochipのデバイスヘッダーで確認済みですが、XC32でのビルドや実機での実行は未実施です。

0.6の新機能：FPGA対応。同じ図からSystemVerilog、Verilog-2001、VHDLを生成し、Artix-7（Nexys A7、Arty A7、Basys 3）やCologne Chip GateMateボード向けのハードウェアを作れます。出力はRunと照合してシミュレーションし、オープンソースツールで合成します。Vivadoでの実行や実機への書き込みはまだ行っていません。

0.6.5 の新機能：MQTT。5つのブロックがプログラムの数値をブローカーへ公開し、コマンドを読み戻します。UART2 に WiFi モジュールをつないだ PIC32MX、自前の WiFi を持つ ESP32、そして自分のパソコン上のブローカーに対する Run で動きます。生成されたクライアントは実際のブローカーで検査していますが、WiFi モジュールやチップは含まれていません。2つの例が付属し、そのうち1つは PIC32 Ethernet Starter Kit II 用です。0.6.7 の新機能：MX695、MX795、スターターキットでは、MQTT はチップ自身の Ethernet ポートから出ることもでき、MPLAB X Harmony プロジェクト用のアプリケーションになります。これは実験的で、実際の Harmony でのビルドはまだ行っていません。画面そのものも英語・ロシア語・アルメニア語から設定で選べます。

0.6.9の新機能：Python 3。同じ図から、Python 3.8以降で追加のインストールなしに動く .py ファイルを1つ生成します。コードウィンドウのRunで実行できます。出力、エラー、終了コードは、各C/C++標準と同様にインタープリターと一致します。

0.7.0の新機能：設定はFileメニューに移り、デバイスファミリーごとのページ（一般、C・C++・Python、Arduino、ESP32、AVR C、PIC32、FPGA）に分かれました。Open ExampleにもArduino、ESP32、PIC32のサブメニューがあり、開くと対応する言語とボードも選ばれます。

0.8.0の新機能：インストーラーにツールチェーン（avr-gccとavrdude、FPGA用のOSS CAD Suite）が含まれるようになり、ベアメタルAVR CとFPGAのフローを設定なしで使えます。Microchipの無料XC32はアプリから直接インストールできます（Settings、PIC32、Get XC32）。入手元はmicrochip.comです。SettingsとDevicesは独立したメニューになりました。

0.7.1の新機能：.deb に加えて、x86-64 の任意の Linux 向け AppImage。Java ランタイムを内蔵した実行ファイル 1 つで、インストールも root も不要です。ボードのプログラムが使えるモジュール（UART、SPI、I2C、MQTT）は上で説明しています。

New in 0.9.0: STM32. The Blue Pill, Black Pill, Nucleo-F401RE, Nucleo-F411RE and STM32F4DISCOVERY take the same diagrams as bare-metal STM32 C (registers only, its own start-up code and linker script) or as Arduino sketches with STMicroelectronics' core, and Upload sends them through an ST-Link with OpenOCD. The installers are now small online installers: the toolchains — arduino-cli, avr-gcc, the Arm GNU Toolchain, OpenOCD and the OSS CAD Suite — are packages of the EVIA server, picked on the first start and updated in place from Settings, Packages and Updates, and the application updates itself the same way. The STM32 code is built with arm-none-eabi-gcc and run in QEMU in CI, but has not yet been run on a board.

0.10.0の新機能：Java、Kotlin、Android。同じ図からJavaまたはKotlinのプログラムを生成し、コードウィンドウでそのままコンパイル・実行できます。Androidアプリも生成でき、EVIA ParadigmaはGradleなしでビルドしてUSB経由でスマートフォンにインストールします。JDKとKotlinコンパイラーはEVIAサーバーのパッケージで、Android SDKはライセンスに同意するとGoogleからダウンロードされます。

0.10.1の新機能：スマートフォンのセンサー。Phone SensorブロックでAndroidスマートフォンの加速度センサー、ジャイロスコープ、GPSを読み取れ、Runではそれらをシミュレートします。File → Open Example → Android Phonesには、Hello world、GPS座標ビューア、モーションテスターの3つのアプリがあります。

0.11.0の新機能：ネイティブ実行ファイル。EVIA Paradigma独自のコンパイラーがブロックを直接Linux x86-64プログラムに変換します。コンピューターにコンパイラー、アセンブラー、リンカーは不要で、プログラムはRunとまったく同じように動作します。EVIA Paradigma Nativeはそれを中心にした2つ目のアプリケーションで、コード生成はなく、Build executableとRun executableだけがあります。

ボードのプログラムが使えるモジュール

UART は選んだポートでバイトや行を送受信し、ボード上では Print の出力先になります。SPI はマスターとしてバイトやバッファを転送し、モードとクロックを選べ、デバイスごとにチップセレクトのピンを指定できます。I2C はデバイスアドレスでレジスタを読み書きし、ほとんどのセンサーはこれで動かします。MQTT は Connect、Publish、Subscribe、Has Message、Read の 5 つのブロックで、プログラムの数値をブローカーへ送り、コマンドを受け取ります。経路は UART2 の WiFi モジュール、ESP32 自身の WiFi、または PIC32 の Ethernet ポート（Harmony アプリケーションとして）です。どのモジュールもインストールするライブラリではなくパレットのブロックで、Run でもチップ上でも同じように動き、対応していないターゲットではブロック名を挙げて拒否します。黙って動かないコードを生成することはありません。

プロジェクト、Git、GitHub

File、New Projectで、プログラム、モジュール用フォルダー、README、Gitリポジトリーを含むフォルダーを作成します。GitメニューからCommit、push、pullを実行できます。Connect to GitHubはGitに設定済みのアカウントを使ってプロジェクトを公開します。アプリがパスワードを要求したり保存したりすることはありません。

  • どこでもVim。コード欄、コードウィンドウ、コミットメッセージでVimキーを使えます。Edit in Vimから実際のVimを開けます。
  • コマンドライン。 evia --run program.evia と evia --gen program.evia --lang c11 -o program.c はスクリプトやMakefileで利用できます。
  • Pythonを自動で検出。 Settings, Pythonは設定なしでpython3、Windowsではpyランチャーを使います。Checkでバージョンを確認できます。
  • ClangまたはGCC。Settingsで切り替えられます。Windowsでは選択したコンパイラーが自動でインストールされるため、Visual Studioは不要です。
  • ダークモード。アプリはIntelliJ IDEA風の外観で、InterとJetBrains Monoを使用します。View、Themeからライト、ダーク、システム設定を選べます。
  • 内蔵ガイド。Help、Guide（F1）では、すべてのブロック、式、クラス機能、ショートカット、Vimキーを英語、ロシア語、アルメニア語で説明しています。
  • PDF版チュートリアル。 Help, Tutorial で全体の手引きを7言語のいずれかで開けます。
  • 設定が道具を取ってきます。 arduino-cli、avr-gcc、FPGA 一式はアプリ専用のフォルダーへダウンロードされ、XC32 は Microchip のページを開きます。

8ステップで最初のプログラムを作成

スクリーンショット付きの完全なチュートリアルを7言語のPDFで利用できます：English、Русский、Հայերեն、Deutsch、简体中文、繁體中文、日本語。アプリのHelp、TutorialやREADMEにも掲載されています。

  1. プロジェクトを作成

    File、New Projectを選択します。Create a Git repositoryはチェックしたままにします。

  2. ループを作成

    Set、For、Printをキャンバスにドラッグし、接続してRunを押します。

  3. クラスを作成

    Edit、New Classを選び、Counterにtotalとcallsフィールドを追加します。

  4. クラスを使う

    Counter.add(x)をループにドラッグし、オブジェクト名をcにします。

  5. コードを見る

    ブロックを右クリックしてView source codeを選択します。

  6. 言語を選ぶ

    C11または任意のC++標準に切り替えると、コードが再生成されます。

  7. コミットして公開

    Git、Commitを選び、その後Connect to GitHubを実行します。

  8. さらに学ぶ

    モジュール、サンプル、ガイド（F1）を確認します。

4ステップで最初のPythonプログラムを作成

どの図もPythonとして実行できます。必要なのはpython.orgのPython 3.8以降だけで、EVIA Paradigmaが自動で見つけます。

  1. Python 3を選ぶ

    ツールバーまたはコードウィンドウのLanguage一覧でPython 3を選びます。

  2. Pythonコードを生成

    F7を押します。ブロックを右クリックしてView source codeを選ぶと、そのブロックが変換された行を確認できます。

  3. コードウィンドウで実行

    Runを押します。Inputに入力したテキストはプログラムに渡され、エラーが起きるとエディターと同じメッセージで停止します。

  4. .pyファイルを保存

    Saveでファイルを書き出せば、どこでも python3 program.py で実行できます。

java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang python -o tutorial.py
python3 tutorial.py
# goto flow and fast values work too
java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang python --flow goto --values fast -o tutorial.py

Settings, Pythonにはコマンドを設定します：python3、Windowsのpyランチャー、またはフルパス。Detectで再検索し、Checkでバージョンを表示します。

4ステップでJava、Kotlin、Androidアプリ

同じ図からJavaやKotlinのプログラム、またはAndroidスマートフォン用のアプリを生成できます。設定からJDKとKotlinコンパイラーをワンクリックで取得でき、Android SDKはライセンスに同意するとGoogleから取得されます。

  1. Java、Kotlin、Androidを選ぶ

    ツールバーまたはコードウィンドウのLanguageリストで選び、F7を押すとコードが表示されます。

  2. コンパイルして実行

    JavaとKotlinでは、コードウィンドウでCompile & Runを押します。Inputに入力したテキストはプログラムに渡されます。

  3. Androidアプリをビルド

    BuildはAndroid SDK自身のツールで数秒でAPKを作成します。GradleやAndroid Studioは不要です。フォルダーはAndroid Studioでも開けます。

  4. スマートフォンにインストール

    USBデバッグをオンにしてスマートフォンを接続し、Install on Phoneを押します。アプリは自動で起動し、Printは画面に、Inputはテキスト欄に表示されます。

java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang java -o Program.java
java Program.java
java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang kotlin -o tutorial.kt
java -jar evia-paradigma.jar --android examples/tutorial.evia ~/apps/tutorial --install

SettingsのJava and KotlinページでJDKとkotlincを、AndroidページでSDK、アプリのIDと名前、スマートフォンを設定します。JavaとKotlinの出力はCIでインタープリターと一致しています。アプリはコンピューター上で確認済みですが、まだスマートフォンでは実行していません。

4ステップで最初のFPGAプログラムを作成

同じblink図からArtix-7およびGateMateボード向けのハードウェアを作れます。完全なチュートリアルのステップ10は上記PDFにあり、ガイドにはFPGAのトピック（F1）があります。

  1. 言語とボードを選ぶ

    言語：SystemVerilog、Verilog-2001、VHDL。ボード：Nexys A7、Arty A7、Basys 3、またはGateMate。

  2. Blinkのサンプルを開く

    File、Open Example、FPGA Boards、Blinkを選びます。ピン名の例：LED0、SW3、BTNC、JA1。

  3. コードを生成

    F7を押します。ピン制約は最初のコメントにあり、コマンドラインでは別ファイルに出力されます。

  4. ビルドして書き込む

    SettingsでVivadoまたはオープンソースツールを選択します。Uploadでボードに書き込みます。

java -jar evia-paradigma.jar --gen examples/fpga/blink.evia --lang sv --board nexys-a7-100t -o blink.sv
# writes blink.sv and blink.xdc
java -jar evia-paradigma.jar --gen examples/fpga/blink.evia --lang vhdl --board olimex-gatemate -o blink.vhd
# writes blink.vhd and blink.ccf

シミュレーションでインタープリターと照合し、オープンソースツールで合成済みです。Vivadoでの実行や実機への書き込みはまだ行っていません。
