# EVIA Paradigma 0.7.1

A generic Linux build that runs without installing anything, and the board modules written up on the site.

## AppImage for any Linux, x86-64

`EVIA-Paradigma-0.7.1-x86_64.AppImage` is one executable file with the application and its Java runtime inside it:

```sh
chmod +x EVIA-Paradigma-0.7.1-x86_64.AppImage
./EVIA-Paradigma-0.7.1-x86_64.AppImage
```

No root, no package manager and nothing written outside the file, so it covers the distributions the `.deb` does
not — Fedora, Arch, openSUSE, NixOS, and live or read-only systems. The `.deb` is unchanged and is still the better
choice on Debian and Ubuntu, because it brings a menu entry, the `evia-paradigma` command and the `.evia` file
association with it.

It carries the same desktop entry, icon and MIME types, so a desktop that integrates AppImages shows it in the
menu and opens `.evia` files with it. The command line works the same way as everywhere else:

```sh
./EVIA-Paradigma-0.7.1-x86_64.AppImage --run examples/example.evia
```

How it is built: `packaging/appimage.sh` takes the application image jpackage has already produced for the `.deb`,
so both installers come from the same build, and packages it with `appimagetool`. The AppDir is smoke-tested
through its `AppRun` and the finished file is smoke-tested again before it is published. If `appimagetool` cannot be
fetched the AppImage is skipped with a warning rather than failing the release, so the `.deb` and the other
installers are never lost to it.

## The modules a board program can use, on the site

The front page now describes the modules instead of how to pan the canvas:

- **UART** — bytes or lines on a chosen port, and what `Print` writes to on a board.
- **SPI** — a byte or a buffer as master, with the mode and clock you pick and a chip-select pin per device.
- **I2C** — registers by device address, which is how most sensors are driven.
- **MQTT** — Connect, Publish, Subscribe, Has Message and Read, over a WiFi module on UART2, an ESP32's own WiFi,
  or a PIC32's Ethernet port as a Harmony application.

It also says what they have in common: each is a block in the palette rather than a library to install, behaves the
same in **Run** as on the chip, and is refused by name on a target that cannot do it instead of compiling into
something that silently will not work. Translated into all seven interface languages.
