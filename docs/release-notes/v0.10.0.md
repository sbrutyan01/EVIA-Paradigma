# EVIA Paradigma 0.10.0

**Java, Kotlin and Android.** The same diagrams now become a Java or Kotlin program, or an app for an Android phone.
An update package: 0.9.0 to 0.9.5 take it from **Settings → Packages and Updates…** and start 0.10.0 the next time.

## Java and Kotlin

- **Language → Java** writes one file with `class Program` (JDK 17 or newer, nothing else); **Language → Kotlin** one
  `.kt` file. **Compile & Run** in the code window compiles and runs them; text typed into Input goes to the program.
- Neither language has `goto`: *Structured* flow writes nested `if`/`else` and `while` loops, and where the wiring is
  not block-structured (and always in *Goto* flow) the diagram becomes a state machine with one branch per block.
- *Safe* values (numbers and text, the interpreter's checks) and *Fast* values (plain `double`s) work as in C++. The
  output, error messages and exit code are the interpreter's, for every example and test in both flows and both value
  modes (108 of 108). The Java compiles with `javac -Xlint:all -Werror` (also for Java 17), the Kotlin with
  `kotlinc -Werror`.
- **Settings → Java and Kotlin**: the JDK is found by itself (`JAVA_HOME`, or the `javac` on PATH); **Get** downloads
  **Eclipse Temurin 25** and **Kotlin 2.4.21**. Both are new packages of the EVIA server (`jdk`, `kotlin`).
- Command line: `--gen program.evia --lang java -o Program.java` (then `java Program.java`), `--lang kotlin`.

## Android apps

- **Language → Android** (or **Devices → Android Phones and Tablets**) makes an Android app of the program: Print lines
  appear on the screen, Input asks in a text field with OK, and **Run again** starts the program over. Android 7.0 and
  newer.
- In the code window, **Build** makes the APK and **Install on Phone** installs it over USB with adb and starts it.
  EVIA Paradigma builds the app itself with the Android SDK's tools (aapt2, kotlinc, R8, zipalign, apksigner) in a few
  seconds: no Gradle and no Android Studio needed, and R8 keeps the APK at tens of kilobytes.
- The folder it writes (the project's `build/android`, or `EVIA Projects/Android/<program>`) is also an ordinary
  Android Studio project (Gradle, Android Gradle plugin 9.5).
- **Settings → Android**: the SDK folder (Android Studio's is found by itself), **Get Android SDK…**, the application id
  (e.g. `am.evia.counter`), the name under the icon, and the phone when several are connected.
- **Get Android SDK…** shows Google's licence, the text from Google's own SDK index, and once you accept it downloads
  platform `android-37.0` (Android 17), build-tools 37.0.0 and platform-tools from Google (about 140 MB). Google's
  licence does not allow passing the SDK on, so it is not a package of the EVIA server.
- Command line: `--android program.evia DIR [--package ID] [--name TEXT] [--build | --install]`, and
  `--android-sdk [--accept-license]` to fetch the SDK.

## Checks

- `check-targets.sh` covers Java and Kotlin; CI installs Kotlin 2.4.21.
- The new `check-android.sh` compiles the app of every example against an Android platform, runs its program part on
  the computer with the console in place of the screen and compares it with the interpreter (54 of 54), and builds one
  APK when the SDK is there.
- A new test program with Russian and Armenian text, `$` and backslashes, for every language.
- The apps have been checked on the computer; they have not yet been run on a phone.
