## The PIC32 Ethernet Starter Kit II

A new entry in the **Board** list: *PIC32 Ethernet Starter Kit II (MX795F512L)*. It builds for the same chip as the
chipKIT Max32, but `LED_BUILTIN` is **RD0**, which is LED1 on the kit, so a program written with `LED_BUILTIN` lights
the right LED without being changed. The kit's other pins are written as usual: LED2 is `RD1`, LED3 `RD2`, SW1 `RD6`,
SW2 `RD7`, SW3 `RD13`.

## New example: MQTT on the starter kit

**File → Open Example → Arduino and ESP32 Boards → MQTT on the PIC32 Ethernet Starter Kit II**

The program shows the whole round trip through a broker:

| Pin | What it does |
|---|---|
| SW1 (RD6, input with pull-up) | its state is published to `evia/esk2/led` |
| LED1 (RD0) | follows the message that comes back from the broker |
| LED2 (RD1) | follows the button directly, so the two can be compared |

In **Run** the broker is simulated on your computer, so the example works without any hardware and prints
`LED1 = 1` when the simulated button is pressed. On the kit, any other MQTT client can drive LED1 by publishing to
the same topic.

Both MQTT programs are now in that menu; in 0.6.5 the first one was in the examples folder but not in the list.

**The kit's Ethernet port is not used.** MQTT goes through a WiFi module with AT firmware on UART2 (RF4 and RF5 on the
expansion connector), as on every other PIC32 chip. MQTT over the built-in Ethernet MAC needs a PHY driver and a
TCP/IP stack and is still not supported.

## Checks

- Every example, for the boards of the three PIC32MX families and both flows, compiles against Microchip's real
  device headers with `-Wall -Wextra -Werror`: **180 of 180** (162 before this example).
- `scripts/check-mqtt.sh` is unchanged and still passes: the generated MQTT client runs against a real broker, and the
  ESP32 sketch compiles as C++.
- The board checks now skip a program whose pin names belong to another chip (the kit's `RD0` means nothing on an
  Arduino), and the MQTT blocks refuse the **ESP32-H2** by name, because that chip has no WiFi.
- The application checks cover the new board and the example.

**Not tested:** no starter kit, WiFi module or broker on a real network was part of this. The pin numbers come from
Microchip's board documentation.
