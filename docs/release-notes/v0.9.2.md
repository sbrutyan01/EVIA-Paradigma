# EVIA Paradigma 0.9.2

A **Linux** menu, next to Git, that builds your own Linux for open boards (**BeagleBone Black** and **Raspberry Pi 5**)
with **Buildroot**, **Yocto** or **OpenWrt**, and writes it to an SD card. An update package: an installed 0.9.0 or
0.9.1 takes it from **Settings → Packages and Updates…** and starts 0.9.2 the next time (or at once with
**Restart Now**).

## Build systems and boards

| Build system | Version | BeagleBone Black | Raspberry Pi 5 | First build |
|---|---|---|---|---|
| Buildroot | 2026.02.3 (LTS) | `beaglebone_defconfig` | `raspberrypi5_defconfig` | about 1 hour, 15 GB |
| Yocto (Poky) | 5.0 Scarthgap (LTS to April 2028) | `beaglebone-yocto` | `raspberrypi5` (meta-raspberrypi) | hours, about 90 GB |
| OpenWrt, Image Builder | 25.12.6 | `omap/generic`, `ti_am335x-bone-black` | `bcm27xx/bcm2712`, `rpi-5` | minutes, 3 GB |
| OpenWrt, from source | 25.12.6 | the same | the same | about 2 hours, 30 GB |

The versions are pinned, so a folder builds the same image later. Yocto is 5.0 Scarthgap, the long-term series that
both Poky (the classic one-repository layout) and meta-raspberrypi carry; Poky has no branch for Yocto 6.0.

## The Linux menu

- **New Linux Image…** opens the Linux Images window: build system, board, folder, host name, root password, SSH server
  (Dropbear), Python 3, the LuCI web interface (OpenWrt) and more packages by the build system's names. For Yocto,
  `core-image-base` or `core-image-minimal`.
- **Build Image** downloads the sources the first time, applies the choices and builds, with the output in the window
  (Stop ends it, children included). **Menuconfig…** opens the build system's own text menu in the desktop's terminal.
- **Write Image to SD Card…** offers only SD cards and USB drives: never a disk with `/`, `/boot`, `/home` or swap on
  it, never a read-only one. It asks twice, unmounts the card, and writes plain or compressed images (`.img`, `.wic`,
  `.gz`, `.bz2`, `.xz`, `.zst`) through pkexec. Elsewhere it names Raspberry Pi Imager or balenaEtcher.
- **Check This Computer** lists the missing tools with the `apt` or `dnf` line that installs them, the free disk space,
  and for Yocto Ubuntu's AppArmor setting that keeps BitBake from user namespaces and a UTF-8 locale.
- **Terminal on the Board** opens the 0.9.1 Terminal for the board's UART (115200 baud) or SSH once it has booted.
- **Linux Images Guide**: a new topic of the guide, in English, Russian and Armenian.

## The folder

Each image is a folder (no spaces in its path; the build systems require it):

- `evia-linux.json`: the choices; **Open Linux Image Folder…** reads it again.
- `build.sh`: `fetch`, `configure`, `build`, `all`, `menuconfig`, `images`. It runs by hand too, e.g. on a build
  server or in WSL 2.
- `secrets/root-password`: owner-only. The image only gets its SHA-512 crypt hash: Buildroot's
  `BR2_TARGET_GENERIC_ROOT_PASSWD`, Yocto's `extrausers`, and an OpenWrt first-boot script. Without a password, root
  logs in without one (Buildroot, Yocto) and OpenWrt asks for one in LuCI.
- `overlay/` (if you make it): files copied into the root file system (Buildroot and OpenWrt).

Command line: `java -jar evia-paradigma.jar --linux DIR --system buildroot|yocto|openwrt|openwrt-source --board bbb|rpi5
[--hostname NAME] [--packages "A B"] [--password-file F] [--python] [--no-ssh] [--web] [--minimal]`.

## Notes

- The builds need Linux (WSL 2 on Windows, a virtual machine on a Mac); the OpenWrt Image Builder needs x86-64.
- BeagleBone Black: hold **S2** at power-on to boot from the card instead of the eMMC. Raspberry Pi 5: the debug UART
  is the 3-pin connector between the HDMI ports.
- `scripts/check-linux.sh` (also in CI) writes all eight combinations and runs their configure steps with stand-in
  tools; it does not download or build the images themselves.
