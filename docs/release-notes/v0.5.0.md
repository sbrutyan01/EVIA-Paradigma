## UART, SPI and I2C blocks

Eight new blocks in the *Board* group of the palette:

| Block | Code | What it does |
|---|---|---|
| UART Open | `9600` | starts the serial port at this baud rate |
| UART Write | `65` | sends one byte |
| UART Read | `c` | stores the next received byte, or -1 if none |
| SPI Open | `1000000` | SPI master at this clock in Hz (mode 0, MSB first) |
| SPI Transfer | `reply = 66` | sends a byte, stores the byte received at the same time |
| I2C Open | `100000` | I2C master at this clock in Hz |
| I2C Write | `80, 0, 42` | address (7-bit), register, value |
| I2C Read | `v = 80, 0` | stores the register's value, or -1 if no device answers |

- **Run** simulates the buses. The UART transmitter is wired to its receiver, so UART Write bytes come back from UART
  Read (and also appear as output text). SPI's input is wired to its output. One I2C device with 256 registers answers
  at address 80; other addresses do not answer. SPI and I2C must be opened first, otherwise Run stops with an error.
- **Arduino sketches** use `Serial`, `SPI.h` and `Wire.h`.
- **AVR C** drives the USART, SPI and TWI registers itself (with timeouts on I2C), for the ATmega328P, ATmega2560
  and ATmega32U4. The UART blocks share the USART used by Print.
- Three new examples under **File > Open Example > Arduino and ESP32 Boards**: UART echo, SPI loopback, I2C memory.

## PIC32 C

A new entry in the **Language** list (`--lang pic32` on the command line): bare-metal C for Microchip's free XC32
compiler. There is no Harmony and no plib; the clock, pins, PWM, ADC, UART, SPI and I2C are set up through the
registers, and only the parts a program uses are included, as with AVR C.

- **Nine chips in three families:** MX1xx/2xx (PIC32MX150F128B, PIC32MX250F128B chipKIT DP32, PIC32MX270F256B),
  MX3xx/4xx (PIC32MX320F128H chipKIT Uno32, PIC32MX340F512H chipKIT uC32, PIC32MX440F256H, PIC32MX460F512L Cerebot MX4cK)
  and MX5xx/6xx/7xx (PIC32MX695F512L chipKIT WF32, PIC32MX795F512L chipKIT Max32).
- **Same blocks, same names:** `pinMode`, `digitalWrite`, `analogRead`, `analogWrite`, `millis`, `delay`, Print and Input
  work as on Arduino and AVR. Pins are numbered `16 * port + bit`, and `RA0` ... `RG15`, `A0` ... `A15` and
  `LED_BUILTIN` are defined. Print and Input use UART1 at 115200 baud.
- **Clock:** the internal 8 MHz oscillator with the PLL at 30 MHz, so no flash wait states are needed.
- **Pins** are fixed per chip family and listed at the top of the generated file (UART1, SPI, I2C1, PWM). The MX1xx/2xx
  family routes them with peripheral pin select.
- **Build and Upload** in the code window: `xc32-gcc`, `xc32-bin2hex`, then an upload command you set in Settings
  (`pic32prog {hex}` by default; `{hex}` is the file and `{device}` the serial port). Settings also holds the path of xc32-gcc.
- **Board** list: the nine chips appear when the language is PIC32 C. `--board KEY` selects one on the command line,
  for example `--lang pic32 --board pic32mx795f512l`.

### What was tested, and what was not

- Every board example, for the boards of all three families in both flows (144 combinations), is compiled by CI with a
  PC gcc (`-Wall -Wextra -Werror`, syntax only) against Microchip's real device headers. That proves that every register
  and bit field the generated code uses exists with the right type.
- The Arduino and AVR bus code runs in simavr and in the real Arduino `Wire` and `SPI` libraries, and matches the
  simulator.
- **The PIC32 code has not been built with XC32 and has not run on a chip.** Pin assignments, the `#pragma config`
  names for a particular part, peripheral timing and the 5xx/6xx/7xx pin differences are written from Microchip's
  datasheets and chipKIT/Pinguino sources and are unproven. The 64-pin MX5xx to MX7xx parts are not offered. Please
  try it on your board and report what you find.
- Microchip's device headers are not part of this repository and are not shipped with the application.

## Tutorial as PDF, in three languages

- **Help > Tutorial (PDF)** opens the tutorial in English, Russian or Armenian (15 pages each, with every screenshot) in
  your PDF viewer. The PDFs are part of the application, so no network is needed.
- The tutorial has a new step 9: the UART, SPI and I2C blocks and the PIC32 language.
- The same PDFs are in [`docs/tutorial`](../tutorial) and on the website. `scripts/build-tutorial-pdf.py` rebuilds them from
  the Markdown sources (`TUTORIAL.md`, `TUTORIAL.ru.md`, `TUTORIAL.hy.md`).
- The jar is about 6 MB bigger because it contains the three PDFs.
