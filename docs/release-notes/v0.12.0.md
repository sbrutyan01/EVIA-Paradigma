# EVIA Paradigma 0.12.0

**The `evia` command: the code generators on the command line, with subcommands.** An update package: 0.9.0 to
0.11.1 take it from **Settings → Packages and Updates…** and start 0.12.0 the next time.

## evia

```
evia gen app.evia -l python -o app.py               # one language (standard output without -o)
evia gen app.evia -l c11,python,java,kotlin -d out/ # several: out/app.c, app.py, app.java, app.kt
evia gen blink.evia -l arduino -b uno -o blink/blink.ino
evia gen top.evia -l sv -b basys3 -o top.sv         # also writes top.xdc
evia watch app.evia -l python -o app.py             # write it again every time app.evia is saved
evia check app.evia                                 # does it generate for every language? (exit code 0/1)
evia run app.evia | native app.evia | android app.evia DIR | new hello.evia
evia langs | boards [LANG] | packages | install ID | remove ID | version | help [gen|watch|check]
```

- `gen` and `watch` take `-l LANGS` (comma separated, or `all`: C99 to C++20, Python, Java, Kotlin), `-o FILE`,
  `-d DIR`, `-b BOARD`, `--flow structured|goto`, `--values safe|fast`, `--net uart|ethernet` and `-q`.
  Two languages with the same file type get the language in the name: `app-c11.c`, `app-c17.c`.
- A board that does not fit the language is refused (`evia boards stm32` lists the ones that do).
- The installers' `evia` / `evia.exe` launcher now starts this command: `evia` alone prints the help instead of
  opening the editor. With the plain jar: `java -jar evia-paradigma.jar gen ...`, or `scripts/install-cli.sh`, which
  puts the jar in `~/.local/share/evia` and the launcher `packaging/cli/evia` in `~/.local/bin` (`evia.cmd` for
  Windows is next to it).
- The older options all still work, also as `evia --gen ...`, `evia --linux ...`.
