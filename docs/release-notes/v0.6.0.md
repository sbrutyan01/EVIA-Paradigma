# EVIA Paradigma 0.6.0

FPGA support: the same diagrams now become hardware for Xilinx Artix-7 and Cologne Chip GateMate boards, written as
SystemVerilog, Verilog-2001 or VHDL.

## Three new languages: SystemVerilog, Verilog-2001, VHDL

New entries in the **Language** list (`--lang sv`, `--lang verilog`, `--lang vhdl` on the command line). All three describe
exactly the same circuit; VHDL is VHDL-2008.

- **A flowchart becomes a state machine.** Every block is one state and takes one clock cycle. Variables are signed
  32-bit registers. The design has one clock input, one LED/pin port per pin the program uses, and `uart_tx` / `uart_rx`
  when it uses the serial port.
- **The board blocks work as on a microcontroller:**
  - *Pin Mode*, *Digital Write*, *Digital Read* (switches and buttons go through two flip-flops) and *Analog Write*
    (8-bit PWM, about 1.5 kHz at 100 MHz);
  - *Delay* counts exact clock cycles, *Millis* is a free-running millisecond counter;
  - *Print* and the *UART* blocks share one serial port (115200 baud, or the rate of UART Open). Numbers are printed in
    decimal, text comes from a table, and every Print ends with a line break.
- **Whole numbers.** `+ - *` wrap around at 32 bits. `/` and `%` truncate toward zero and give 0 when the divisor is 0;
  a division takes about 35 clock cycles and uses one shared divider. This is the one place where the generated hardware
  and **Run** differ: Run uses double numbers, so `5 / 2` is 2.5 in Run and 2 on the FPGA. The new examples avoid it.
- **Pins are fixed when the design is built**, so a pin must be a constant: a number, or a name. The same names work on
  every board and in Run:

  | Names | Pins |
  |---|---|
  | `LED0` ... `LED15` | the LEDs (`LED_BUILTIN` is `LED0`) |
  | `SW0` ... `SW15` | slide switches |
  | `BTNC` `BTNU` `BTNL` `BTNR` `BTND`, or `BTN0` ... `BTN3` | push buttons |
  | `JA1` `JA2` `JA3` `JA4` `JA7` `JA8` `JA9` `JA10`, and `JB`, `JC`, `JD` | Pmod connectors (input or output, decided by how the program uses the pin) |

  A pin the chosen board does not have is an error that lists the pins it has. A pin cannot be both read and written.
- **Not supported when generating for an FPGA yet** (the error names the block): classes, Input, Analog Read, SPI and I2C,
  and text in variables or comparisons (text works in Print).
- The generated file starts with a comment that holds the pin constraints; with `-o FILE` the command line also writes
  them next to it as `.xdc` (Vivado) or `.ccf` (GateMate).

The two GateMate boards are limited on purpose: only pins whose location is known from the manufacturers' files are
offered. More can be added in `Fpga.java`.

## Build and Upload

**Build** and **Upload** in the code window, with the **Board** list next to the language, work for FPGAs too:

- **Artix-7, Vivado:** `vivado -mode batch` reads the design and constraints, synthesises, places, routes and writes
  `top.bit`; Upload programs the board through the Hardware Manager.
- **Artix-7, open source (openXC7):** yosys `synth_xilinx`, nextpnr-xilinx, Project X-Ray `fasm2frames` and `xc7frames2bit`,
  then openFPGALoader.
- **GateMate** (open source only): yosys `synth_gatemate`, nextpnr-himbaechel, gmpack, then openFPGALoader.
- **Settings** has the Artix-7 flow (*Vivado* or *Open source*) and the path of each tool. VHDL through yosys needs its
  ghdl plugin. Settings is now scrollable.
- `Fpga.buildSteps` holds the commands, and the application checks cover them.

## Examples

Six programs under **File > Open Example > FPGA Boards**: blink, switches control LEDs, a binary counter on the LEDs that
also prints over the serial port, a button counter, fading an LED with PWM, and a serial hello with echo. Opening one
switches the language to SystemVerilog. They give the same pin changes and text in Run and in the hardware.

## What was tested, and what was not

New CI job `fpga` (`scripts/check-fpga.sh` runs the same on your computer, with the OSS CAD Suite on the PATH):

- **Simulation against the interpreter.** Nine test programs (arithmetic, comparisons and logic, all three loops, nested
  loops, Print edge cases such as negative numbers and the smallest 32-bit value, pins and switches over time, Millis and
  Delay, the serial port in loopback, PWM duty, and about 300 divisions against a Python 32-bit reference) are generated in all
  three languages and simulated, SystemVerilog and Verilog with Icarus Verilog and VHDL with GHDL, at a lowered clock.
  Pin changes (within 2 ms), printed text and serial bytes must equal what the interpreter does; PWM duty is measured.
  27 of 27 agree.
- **Synthesis.** Every example and test program is synthesised by yosys for Artix-7 (`synth_xilinx`) in all three
  languages, and the GateMate designs are placed, routed and packed into a bitstream with nextpnr-himbaechel and gmpack.
- The application checks cover the new languages and boards, the constraint files, the refusals (a fractional number,
  text in a variable, a pin the board lacks, writing a switch, and so on) and the build commands.

**Not tested:** nothing here ran Vivado, nextpnr-xilinx/openXC7 or openFPGALoader, and no design was loaded into a board.
The Artix-7 pin locations come from Digilent's published master constraint files, and the GateMate ones from Olimex's
KiCad design and Cologne Chip's example; the `.xdc` and `.ccf` text follows their formats but was not run through a
vendor tool, except that nextpnr-himbaechel accepted the GateMate files. Whether the Olimex board's debug UART reaches the
USB port depends on its RP2040 firmware. Please try it on your board and report what you find.

## Other changes

- A variable can no longer be named like a board pin (`LED0`, `SW3`, `BTNC`, `JA1` ...), as with `A0` and `HIGH` before.
- The guide (English, Russian, Armenian) and the tutorial (new step 10) cover FPGAs; the tutorial PDFs are rebuilt.
- The Flow list is disabled for the FPGA languages (a state machine has no structured or goto form).
