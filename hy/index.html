Նկարեք ծրագիրը։
Ընտրեք նրա լեզուն։

EVIA Paradigma-ն տեսողական ծրագրավորում է նրանց համար, ովքեր ուզում են տեսնել, թե ինչ է ստանում մեքենան։ Սխեման ինքն է ծրագիրը, իսկ լեզուն ընդամենը կարգավորում է։ Միացրեք բլոկները կտավի վրա, գործարկեք դրանք, ապա ընտրեք, թե ինչ դառնան՝ C99-ից մինչև C++20 (Clang կամ GCC), Python 3, Java կամ Kotlin ծրագիր, Android հավելված, Arduino սքեթչ, bare-metal C՝ AVR, PIC32 կամ STM32 չիպի համար, կամ SystemVerilog, Verilog կամ VHDL՝ FPGA-ի համար։

Ներբեռնել 0.12.1 Կոդը GitHub-ում

Windows, macOS և Linux։ Անվճար, բաց կոդ, MIT լիցենզիա։

Ինչ է անում ծրագիրը

Ծրագիրը բլոկներ և կապեր է

Start, Set, Input, Print, If/Else, For, While և Do-While բլոկներ են, իսկ դրանց միջև կապերը որոշում են կատարման հերթականությունը։ Սեղմեք Run, և կատարվող բլոկը լուսավորվում է։ Արտահայտություններն աշխատում են թվերի և տեքստի հետ՝ && || !, համեմատություններ և սովորական թվաբանություն։

Դասեր, օբյեկտներ և մոդուլներ

Դասն ունի սկզբնական արժեքներով դաշտեր, կոնստրուկտոր և մեթոդներ, և յուրաքանչյուր մեթոդ առանձին բլոկ-սխեմա է՝ Enter-ից մինչև Exit։ Յուրաքանչյուր Exit դառնում է կանչող բլոկի ելք։ Նույն օբյեկտի անունով բլոկներն աշխատում են մեկ օբյեկտի հետ։ Դասերը կարելի է պահել որպես մոդուլներ (.eviam) և ներմուծել այլ ծրագրերում։

Մեկ սխեմա՝ տասնինը լեզու

Սխեման ասում է, թե ծրագիրը ինչ է անում, ոչ թե ինչով է գրված։ Նույն կտավը դառնում է C-ի և C++-ի ութ ստանդարտ, Python 3, Java, Kotlin, Android հավելված, Arduino սքեթչ, bare-metal C՝ AVR, PIC32 կամ STM32 համար, կամ SystemVerilog, Verilog-2001 և VHDL՝ FPGA-ի համար, իսկ Run-ը կատարում է հենց սխեման, որպեսզի դրա արդյունքը կարողանաք համեմատել դրանցից ցանկացածի հետ։ Եթե նպատակը չի կարող պահել բլոկը, սխալը նշում է այդ բլոկը՝ փոխանակ լուռ փոխի ծրագրի իմաստը։

C-ի և C++-ի ութ ստանդարտ, գրելու երկու եղանակ

Գործիքագոտուց ընտրեք C99, C11, C17, C++98, C++11, C++14, C++17 կամ C++20։ Structured-ը գրում է if/else, ցիկլեր և switch, իսկ Goto-ն յուրաքանչյուր բլոկ դարձնում է նշիչ, յուրաքանչյուր կապ՝ անցում։ Safe արժեքները պահում են տեքստը և ինտերպրետատորի բոլոր ստուգումները, իսկ Fast արժեքները պարզ double-ներ են՝ առանց կատարման ժամանակի ստուգումների։ C-ի runtime-ը պարունակում է միայն այն, ինչ օգտագործում է ծրագիրը, ուստի կոդը կոմպիլյացվում է առանց նախազգուշացումների -Wall -Wextra -Wpedantic -Werror-ով։

Python 3՝ առանց կոմպիլյացիայի

Ընտրեք Python 3, և նույն սխեման կդառնա մեկ .py ֆայլ, որն աշխատում է Python 3.8 և ավելի նոր տարբերակներում՝ առանց փաթեթների և կոմպիլյատորի։ Դասերը դառնում են Python-ի դասեր, իսկ ծրագրի փոփոխականները՝ մոդուլի գլոբալ փոփոխականներ։ Կոդի պատուհանի Run-ը գործարկում է ծրագիրը, իսկ Input-ում մուտքագրված տեքստը փոխանցվում է նրան։ Python-ում goto չկա, ուստի Structured-ը գրում է if/else և while ցիկլեր, իսկ Goto-ն դառնում է փոքր վիճակների մեքենա՝ յուրաքանչյուր բլոկի համար մեկ ճյուղով։ Print-ը, Input-ը, թվերի գրառումը և բոլոր սխալների հաղորդագրությունները նույնն են, ինչ ինտերպրետատորինը։

Ցանկացած բլոկի կոդը

Սեղմեք բլոկի վրա մկնիկի աջ կոճակով և ընտրեք View source code։ Կբացվի գեներացված ֆայլը, որտեղ ընդգծված են հենց այն տողերը, որոնց վերածվել է բլոկը։ Նույնն աշխատում է ամբողջ մեթոդի կամ դասի համար՝ ձեր ընտրած ցանկացած լեզվով։ Compile & Run-ը անմիջապես կառուցում է կոդը Clang-ով կամ GCC-ով, իսկ Windows-ում ծրագիրն ինքն է տեղադրում llvm-mingw կամ WinLibs GCC, Visual Studio պետք չէ։

Arduino և ESP32 տախտակներ

Pin Mode, Digital Write և Read, Analog Read և Write, Delay և Millis նույնպես բլոկներ են։ Մեկ Arduino սքեթչ կառուցվում է Uno, Nano, Mega 2560, Leonardo, Micro և Pro Mini, ինչպես նաև ESP32, ESP32-S2, -S3, -C3, -C6 և -H2 տախտակների համար։ Run-ը համակարգչի վրա նմանակում է Uno-ն և ցույց է տալիս պինների յուրաքանչյուր փոփոխություն, այնպես որ ծրագիրը կարող եք փորձել դեռ մինչև տախտակը ձեռքի տակ ունենալը։ UART-ը, SPI-ը, I2C-ն և MQTT-ն նույնպես բլոկներ են։

Առանց Arduino-ի՝ ուղիղ ռեգիստրներով

AVR C-ն ծրագիրը գրում է ATmega328P, ATmega2560 կամ ATmega32U4-ի համար՝ առանց Arduino միջուկի. պորտերը, թայմերները, PWM-ը, ԱԹՓ-ն և UART-ը կարգավորվում են ընթեռնելի C-ով։ avr-gcc-ն այն կառուցում է մոտ 4 ԿԲ-ով, իսկ Upload-ը avrdude-ով բեռնում է այն տախտակի վրա։ Յուրաքանչյուր օրինակ գործարկվում է simavr սիմուլյատորում և համեմատվում ինտերպրետատորի հետ։

Նորություն 0.5-ում. PIC32 C-ն նույնն անում է ինը PIC32MX չիպի համար Microchip-ի XC32-ով, իսկ UART-ը, SPI-ն և I2C-ն դարձել են բլոկներ՝ Run-ում և տախտակների բոլոր երեք լեզուներում։ PIC32-ի կոդը ստուգվել է Microchip-ի վերնագրային ֆայլերով, բայց դեռ չի կառուցվել XC32-ով և չի աշխատել չիպի վրա։

Նորություն 0.6-ում՝ FPGA աջակցություն։ SystemVerilog, Verilog-2001 և VHDL նույն սխեման դարձնում են սարքակազմ Artix-7 (Nexys A7, Arty A7, Basys 3) և Cologne Chip GateMate տախտակների համար։ Արդյունքը սիմուլացվել է Run-ի համեմատ և սինթեզվել բաց գործիքներով, բայց չի անցել Vivado-ով և չի բեռնվել տախտակի մեջ։

Նորություն 0.6.5-ում՝ MQTT։ Հինգ բլոկ ծրագրի թվերը հրապարակում են բրոքերին և կարդում հրամաններ՝ PIC32MX-ի վրա UART2-ի WiFi մոդուլով, ESP32-ի վրա սեփական WiFi-ով, իսկ Run-ում՝ ձեր համակարգչի բրոքերով։ Ստեղծված հաճախորդը ստուգվում է իրական բրոքերով. ոչ WiFi մոդուլ, ոչ չիպ այդ ստուգման մաս չեն եղել։ Դրան ուղեկցում են երկու օրինակ, որոնցից մեկը՝ PIC32 Ethernet Starter Kit II-ի համար։ Նորություն 0.6.7-ում՝ միջերեսն ինքը անգլերեն, ռուսերեն կամ հայերեն է՝ ընտրվում է Կարգավորումներում։

Նորություն 0.6.9-ում՝ Python 3։ Նույն սխեման դառնում է մեկ .py ֆայլ, որն աշխատում է Python 3.8 և ավելի նոր տարբերակներում՝ առանց որևէ այլ բան տեղադրելու, իսկ կոդի պատուհանի Run կոճակը գործարկում է այն։ Արդյունքը, սխալները և ավարտի կոդը համընկնում են ինտերպրետատորի հետ, ինչպես C-ի և C++-ի յուրաքանչյուր ստանդարտում։

Նորություն 0.7.0-ում՝ կարգավորումները File ընտրացանկում են, յուրաքանչյուր սարքերի ընտանիքի համար առանձին էջով՝ ընդհանուր, C, C++ և Python, Arduino, ESP32, AVR C, PIC32 և FPGA, իսկ Open Example-ը ունի առանձին Arduino, ESP32 և PIC32 ենթացանկեր, որոնք միանգամից ընտրում են համապատասխան լեզուն և տախտակը։

Նորություն 0.8.0-ում՝ տեղադրիչներն իրենց հետ բերում են գործիքները՝ avr-gcc-ն avrdude-ով և OSS CAD Suite-ը FPGA-ի համար, ուստի AVR-ի bare-metal C-ն և FPGA-ի հոսքերն աշխատում են առանց որևէ կարգավորման։ Microchip-ի անվճար XC32-ը տեղադրվում է հենց հավելվածից (Settings, PIC32, Get XC32)՝ անմիջապես microchip.com-ից։ Settings-ը և Devices-ը այժմ առանձին ընտրացանկեր են։

Նորություն 0.7.1-ում՝ AppImage ցանկացած Linux-ի համար x86-64-ի վրա, .deb-ի կողքին՝ մեկ գործարկելի ֆայլ Java-ի հետ ներսում, ոչինչ տեղադրելու կարիք չկա և root չի պահանջվում։ Տախտակի ծրագրին հասանելի մոդուլները նկարագրված են վերևում՝ UART, SPI, I2C և MQTT։

New in 0.9.0: STM32. The Blue Pill, Black Pill, Nucleo-F401RE, Nucleo-F411RE and STM32F4DISCOVERY take the same diagrams as bare-metal STM32 C (registers only, its own start-up code and linker script) or as Arduino sketches with STMicroelectronics' core, and Upload sends them through an ST-Link with OpenOCD. The installers are now small online installers: the toolchains — arduino-cli, avr-gcc, the Arm GNU Toolchain, OpenOCD and the OSS CAD Suite — are packages of the EVIA server, picked on the first start and updated in place from Settings, Packages and Updates, and the application updates itself the same way. The STM32 code is built with arm-none-eabi-gcc and run in QEMU in CI, but has not yet been run on a board.

Նորը 0.10.0-ում՝ Java, Kotlin և Android։ Նույն սխեման դառնում է Java կամ Kotlin ծրագիր, որը կոմպիլացվում և գործարկվում է կոդի պատուհանից, կամ Android հավելված, որը EVIA Paradigma-ն կառուցում է առանց Gradle-ի և USB-ով տեղադրում հեռախոսում։ JDK-ն և Kotlin-ի կոմպիլյատորը EVIA սերվերի փաթեթներ են, իսկ Android SDK-ն ներբեռնվում է Google-ից՝ նրա լիցենզիան ընդունելուց հետո։

Նորը 0.10.1-ում՝ հեռախոսի սենսորները։ «Հեռախոսի սենսոր» բլոկը կարդում է Android հեռախոսի արագացմաչափը, գիրոսկոպը և GPS-ը, իսկ Run-ը դրանք նմանակում է։ «Ֆայլ → Բացել օրինակ → Android հեռախոսներ» ընտրացանկում կա երեք պատրաստի հավելված՝ Hello world, GPS կոորդինատների դիտիչ և շարժման թեստ։

Նորը 0.11.0-ում՝ կատարվող ծրագրեր։ EVIA Paradigma-ի սեփական կոմպիլյատորը բլոկներն ուղղակի վերածում է Linux x86-64 ծրագրի՝ առանց համակարգչում կոմպիլյատորի, ասեմբլերի և կապակցիչի, և ծրագիրն աշխատում է ճիշտ ինչպես Run-ը։ EVIA Paradigma Native-ը դրա վրա հիմնված երկրորդ հավելվածն է՝ առանց կոդի գեներացման, միայն «Կառուցել ծրագիրը» և «Գործարկել ծրագիրը»։

Մոդուլներ, որոնք հասանելի են տախտակի ծրագրին

UART-ն ուղարկում և ստանում է բայթեր կամ տողեր նշված պորտով, և հենց այնտեղ է գրում Print-ը տախտակի վրա։ SPI-ն որպես master փոխանցում է բայթ կամ բուֆեր՝ ընտրված ռեժիմով և հաճախությամբ, և ամեն սարքի համար առանձին ընտրության ոտքով։ I2C-ն կարդում և գրում է ռեգիստրներ սարքի հասցեով՝ այդպես են աշխատում սենսորների մեծ մասը։ MQTT-ն հինգ բլոկ է՝ Connect, Publish, Subscribe, Has Message և Read, որոնք ծրագրի թվերը ուղարկում են բրոքերին և հրահանգներ ստանում հետ՝ UART2-ի WiFi մոդուլով, ESP32-ի սեփական WiFi-ով կամ PIC32-ի Ethernet պորտով՝ որպես Harmony հավելված։ Յուրաքանչյուր մոդուլ բլոկ է գունապնակում, ոչ թե տեղադրելու գրադարան. Run-ում այն աշխատում է այնպես, ինչպես չիպի վրա, իսկ այն թիրախի վրա, որը չի աջակցում, մերժումը անվանում է բլոկը, փոխանակ հավաքի կոդ, որը լուռ չի աշխատի։

Նախագծեր, Git և GitHub

File, New Project-ը ստեղծում է թղթապանակ՝ ծրագրով, մոդուլների թղթապանակով, README-ով և Git պահոցով։ Commit, push և pull՝ Git ընտրացանկից։ Connect to GitHub-ը հրապարակում է նախագիծն այն հաշվով, որն արդեն օգտագործում է ձեր git-ը։ Ծրագիրը երբեք գաղտնաբառ չի խնդրում և չի պահում։

  • Vim ամենուր։ Կոդի դաշտերում, կոդի պատուհանում և commit-ների հաղորդագրություններում աշխատում են Vim ստեղները, իսկ Edit in Vim-ը բացում է իսկական Vim-ը։
  • Հրամանային տող։ evia --run program.evia և evia --gen program.evia --lang c11 -o program.c՝ սկրիպտների և Makefile-երի համար։
  • Python-ը գտնվում է ինքնուրույն։ Settings, Python-ն օգտագործում է python3-ը կամ Windows-ում py գործարկիչը՝ առանց կարգավորման. Check-ը ցույց է տալիս տարբերակը։
  • Clang կամ GCC։ Դրանք փոխվում են Settings-ում, իսկ Windows-ում ցանկացածն ինքն է տեղադրվում, Visual Studio պետք չէ։
  • Մուգ թեմա. Ծրագիրը նման է IntelliJ IDEA-ին՝ Inter և JetBrains Mono տառատեսակներով։ View, Theme-ը ընտրում է բաց, մուգ կամ համակարգի թեմա։
  • Ներկառուցված ուղեցույց. Help, Guide (F1)-ը բացատրում է յուրաքանչյուր բլոկ, արտահայտությունները, դասերի հնարավորությունները, ստեղնային համակցությունները և Vim ստեղները՝ անգլերեն, ռուսերեն և հայերեն։
  • Ուսուցումը PDF-ով։ Help, Tutorial-ը բացում է ամբողջ ուղեցույցը յոթ լեզուներից ցանկացածով։
  • Կարգավորումները բերում են գործիքները։ arduino-cli-ն, avr-gcc-ն և FPGA-ի հավաքածուն ներբեռնվում են հավելվածի սեփական պանակը, իսկ XC32-ը բացում է Microchip-ի էջը։

Առաջին ծրագիրը ութ քայլով

Բոլոր սքրինշոթներով ամբողջական քայլ առ քայլ ուսուցումը հասանելի է PDF-ով յոթ լեզվով՝ English, Русский, Հայերեն, Deutsch, 简体中文, 繁體中文, 日本語։ Այն հասանելի է նաև ծրագրի Help, Tutorial ընտրացանկում և README-ում։

  1. Ստեղծեք նախագիծ

    File, New Project։ Թողեք Create a Git repository-ն նշված։

  2. Կառուցեք ցիկլ

    Քաշեք Set, For և Print բլոկները կտավի վրա, միացրեք դրանք և սեղմեք Run։

  3. Ստեղծեք դաս

    Edit, New Class։ Counter դասին տվեք total և calls դաշտերը։

  4. Օգտագործեք դասը

    Քաշեք Counter.add(x)-ը ցիկլի մեջ և օբյեկտն անվանեք c։

  5. Տեսեք կոդը

    Աջ սեղմում բլոկի վրա, View source code։

  6. Ընտրեք լեզուն

    Անցեք C11-ի կամ C++-ի ցանկացած ստանդարտի, և կոդը նորից կգեներացվի։

  7. Commit և հրապարակում

    Git, Commit, ապա Connect to GitHub։

  8. Շարունակեք

    Մոդուլներ, օրինակներ և ուղեցույց (F1)։

Ձեր առաջին Python ծրագիրը չորս քայլով

Ցանկացած սխեմա աշխատում է որպես Python ծրագիր։ Պետք է միայն Python 3.8 կամ ավելի նոր տարբերակ python.org-ից, որը EVIA Paradigma-ն ինքն է գտնում։

  1. Ընտրեք Python 3

    Ընտրեք Python 3-ը Language ցանկում՝ գործիքագոտում կամ կոդի պատուհանում։

  2. Գեներացրեք Python կոդը

    Սեղմեք F7։ Աջ սեղմեք բլոկի վրա և ընտրեք View source code՝ տեսնելու, թե ինչ տողերի է այն վերածվել։

  3. Գործարկեք կոդի պատուհանում

    Սեղմեք Run։ Input-ում մուտքագրված տեքստը փոխանցվում է ծրագրին, իսկ սխալը կանգնեցնում է այն նույն հաղորդագրությամբ, ինչ խմբագրիչում։

  4. Պահպանեք .py ֆայլը

    Save-ը գրում է ֆայլը, և այն աշխատում է ցանկացած տեղում՝ python3 program.py հրամանով։

java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang python -o tutorial.py
python3 tutorial.py
# goto flow and fast values work too
java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang python --flow goto --values fast -o tutorial.py

Settings, Python-ը պահում է հրամանը՝ python3, Windows-ում py գործարկիչը կամ ամբողջական ուղի։ Detect-ը նորից է փնտրում այն, իսկ Check-ը ցույց է տալիս տարբերակը։

Java, Kotlin և Android հավելվածներ՝ չորս քայլով

Նույն սխեման դառնում է Java կամ Kotlin ծրագիր կամ Android հեռախոսի հավելված։ Կարգավորումները մեկ սեղմումով ներբեռնում են JDK-ն և Kotlin-ի կոմպիլյատորը, իսկ Android SDK-ն՝ Google-ից, երբ ընդունեք նրա լիցենզիան։

  1. Ընտրեք Java, Kotlin կամ Android

    Ընտրեք այն Language ցանկում՝ գործիքագոտում կամ կոդի պատուհանում, և սեղմեք F7՝ կոդը տեսնելու համար։

  2. Կոմպիլացրեք և գործարկեք

    Java-ի և Kotlin-ի համար սեղմեք «Կոմպիլացնել և գործարկել» կոդի պատուհանում։ Input դաշտում մուտքագրված տեքստը փոխանցվում է ծրագրին։

  3. Կառուցեք Android հավելվածը

    «Կառուցել» կոճակը մի քանի վայրկյանում ստեղծում է APK՝ Android SDK-ի սեփական գործիքներով, առանց Gradle-ի և Android Studio-ի։ Թղթապանակը, այնուամենայնիվ, բացվում է նաև Android Studio-ում։

  4. Տեղադրեք այն հեռախոսում

    Միացրեք USB վրիպազերծումը, միացրեք հեռախոսը և սեղմեք «Տեղադրել հեռախոսում»։ Հավելվածն ինքն է գործարկվում. Print-ը էկրանին է, Input-ը՝ տեքստային դաշտում։

java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang java -o Program.java
java Program.java
java -jar evia-paradigma.jar --gen examples/tutorial.evia --lang kotlin -o tutorial.kt
java -jar evia-paradigma.jar --android examples/tutorial.evia ~/apps/tutorial --install

«Կարգավորումներ → Java և Kotlin»-ում են JDK-ն և kotlinc-ը, «Կարգավորումներ → Android»-ում՝ SDK-ն, հավելվածի id-ն և անունը, և հեռախոսը։ Java-ի և Kotlin-ի ելքը CI-ում համընկնում է ինտերպրետատորի հետ. հավելվածները ստուգված են համակարգչում, բայց դեռ չեն գործարկվել հեռախոսում։

Ձեր առաջին FPGA ծրագիրը չորս քայլով

Նույն թարթման սխեման դառնում է սարքակազմ Artix-7 և GateMate տախտակների համար։ Ամբողջական ձեռնարկը՝ քայլ 10, վերևի PDF-ում է, իսկ ուղեցույցում կա FPGA թեմա (F1)։

  1. Ընտրեք լեզու և տախտակ

    Լեզու՝ SystemVerilog, Verilog-2001 կամ VHDL։ Տախտակ՝ Nexys A7, Arty A7, Basys 3 կամ GateMate տախտակ։

  2. Բացեք Blink օրինակը

    File, Open Example, FPGA Boards, Blink։ Կոնտակտները անուններ են՝ LED0, SW3, BTNC, JA1։

  3. Ստեղծեք կոդը

    Սեղմեք F7։ Կոնտակտների սահմանափակումները առաջին մեկնաբանության մեջ են, իսկ հրամանի տողը դրանք գրում է առանձին ֆայլում։

  4. Կառուցում և բեռնում

    Vivado կամ բաց գործիքներ՝ ընտրվում է Կարգավորումներում։ Upload-ը ծրագրավորում է տախտակը։

java -jar evia-paradigma.jar --gen examples/fpga/blink.evia --lang sv --board nexys-a7-100t -o blink.sv
# writes blink.sv and blink.xdc
java -jar evia-paradigma.jar --gen examples/fpga/blink.evia --lang vhdl --board olimex-gatemate -o blink.vhd
# writes blink.vhd and blink.ccf

Յուրաքանչյուր տեղադրիչ ունի իր Java միջավայրը, ուստի ուրիշ ոչինչ տեղադրել պետք չէ։ Գեներացված կոդը կոմպիլյացնելու համար անհրաժեշտ է Clang կամ GCC (Windows-ում ծրագիրն ինքն է տեղադրում դրանցից ցանկացածը), իսկ գեներացված Python-ի համար պետք է միայն Python 3.8 կամ ավելի նոր տարբերակ։

Ստուգված սեփական ինտերպրետատորով

Յուրաքանչյուր փոփոխության ժամանակ CI-ն գեներացնում է բոլոր օրինակներն ու թեստային ծրագրերը լեզվի, հոսքի և արժեքների բոլոր 44 համակցություններով, կոմպիլյացնում է՝ նախազգուշացումները համարելով սխալներ (Python-ը՝ ստուգում է), գործարկում և համեմատում stdout-ը, stderr-ը և ելքի կոդը ինտերպրետատորի հետ։

Arduino սքեթչները կառուցվում են նաև բոլոր 12 տախտակների համար, այդ թվում՝ ESP32 (70 կառուցում՝ առանց նախազգուշացումների)։ PIC32-ի օրինակները կոմպիլացվում են (միայն շարահյուսություն) Microchip-ի վերնագրերով (144-ից 144)։ FPGA-ի յուրաքանչյուր օրինակ և թեստ սինթեզվում է yosys-ով Artix-7-ի համար, իսկ GateMate նախագծերը տեղակայվում, երթուղավորվում և փաթեթավորվում են բիթսթրիմների մեջ. Vivado-ն, openXC7-ը և իրական տախտակները CI-ում չեն։ MQTT հաճախորդը կառուցվում է կառուցման մեքենայի վրա և ստուգվում իրական բրոքերով։ Ինչպես նաև հավելվածի, մոդուլների, նախագծերի, Git-ի, մասշտաբավորման և կտավի տեղափոխման ստուգումներ իրական պատուհանում։ Մանրամասները՝ GitHub Actions-ում։
